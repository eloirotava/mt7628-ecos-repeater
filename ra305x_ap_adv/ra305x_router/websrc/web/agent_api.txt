# Device API

MT7628KN Wi-Fi extender. All paths are relative to the current device origin. When an admin password is set, every page except /llms.txt and /agent_api.txt requires HTTP Basic authentication with the admin user and password (sent unencrypted over HTTP). With no admin password, no authentication is required. No cloud service is used.

Requests that change settings use POST with application/x-www-form-urlencoded fields. Responses are OK when accepted, or ERROR: followed by an explanation. GET requests to these endpoints do not change settings.

## Read current state

GET /wifi_state.html returns JSON:
- busy (0 or 1), revision (apply counter), error (0 on success; -3 means saving failed), stage, saved (1 when the last apply was written and verified in flash).
- mode (ap or repeater), ssid (device network), device_security (open or wpa2), channel.
- uplink (repeater uplink SSID), security (uplink driver authentication name), uplink_status (repeater only: driver connection text, for example "Connected" or "Disconnected").
- admin_user, admin_password_set (0 or 1), telnet (1 when Telnet logins are accepted).
- chip, version, build (UNIX time), uptime (seconds).
- wireguard: enabled, address (tunnel address/prefix), peer_public_key, endpoint, port, keepalive, preshared_key_set, public_key (this device, base64; new after every factory reset), state (off, starting, clock, handshake, connected or error), status, handshake_age (seconds, -1 before the first), rx_bytes and tx_bytes.
- ntun: enabled, host, port, local_port, server_key (public), public_key (this device's ntun public key, 64 hex; empty for a few seconds after boot; new after every factory reset), state (off, starting, connecting, connected or error), status (text) and status_age (seconds).

Passwords are never returned.

## Scan for networks

GET /wifi_scan.html runs a site survey (about 3 seconds) and returns JSON {"error": "", "raw": "<driver table>"}. error is "busy" while settings are being applied. raw is a fixed-width table whose header line starts with "Ch  SSID  BSSID  Security  Siganl(%)W-Mode"; locate columns by the header positions. SSIDs with non-ASCII bytes appear as 0x followed by hex (decode as UTF-8). Empty SSIDs are hidden networks. Security values such as WPA2PSK/AES map to wpa2, WPA1PSKWPA2PSK/TKIPAES to mixed and NONE to open; WPA3/SAE and enterprise networks are unsupported.

## Apply Wi-Fi settings

POST /wifi_apply.html with:
- MODE: ap (Ethernet uplink) or repeater (2.4 GHz Wi-Fi uplink). Both modes bridge clients to the upstream network, take the management address by upstream DHCP and run no DHCP server.
- SSID: device network name, 1-32 UTF-8 bytes, no control characters.
- DEVICE_SECURITY: open or wpa2.
- PASSWORD: device WPA2-Personal password, 8-63 printable ASCII characters. With DEVICE_SECURITY=wpa2, an empty PASSWORD keeps the current password (only if the network already uses WPA2). Ignored for open.
- CHANNEL: 1-13. In repeater mode use the channel of the uplink network.
- UPLINK_SSID: repeater only, 1-32 UTF-8 bytes.
- UPLINK_SECURITY: repeater only: wpa2 (AES), mixed (WPA/WPA2 TKIP/AES) or open.
- UPLINK_PASSWORD: 8-63 printable ASCII characters for secured uplinks. Empty keeps the stored password when UPLINK_SSID is unchanged.

Settings are saved to flash and applied without a restart. Invalid fields are rejected before anything changes. OK means accepted, not connected: poll /wifi_state.html until busy is 0 and revision has increased, then require error=0 and saved=1 and verify mode, ssid, channel, uplink and, in repeater mode, uplink_status. A wrong uplink password keeps the device network running and shows a disconnected uplink_status. Also test traffic from a Wi-Fi client.

Access point mode needs Ethernet to the router. Repeater mode uses wireless backhaul: disconnect an Ethernet uplink to the same network before applying to avoid a bridge loop. Reconnect to the configured device SSID if Wi-Fi drops; the DHCP address may change.

## Administration

POST /admin_apply.html with USER (1-31 printable ASCII characters, no spaces or colons), PASSWORD and CONFIRM (equal; 8-63 printable ASCII characters without spaces, or both empty to remove the password) and CURRENT (the current admin password; required when one is set). Credentials are saved to flash immediately and apply to HTTP and Telnet. After setting a password, sign in again with the new credentials. Removing the password disables Telnet.

## System

POST /system_apply.html with ACTION=reboot (restart) or ACTION=factory (erase settings, restore factory defaults and restart). The connection drops; the device returns after about one minute. Factory defaults: open network "Extender-<Wi-Fi MAC>", no admin password, Telnet disabled, ntun and WireGuard disabled with new device keys. The reset button does the same when held for more than 4 seconds; a short press restarts.

## Remote access (ntun)

POST /ntun_apply.html with ENABLED (0 or 1), HOST (host name or IPv4 address, letters, numbers, dots and hyphens, up to 63), PORT (1-65535; the ntun default is 8222), SERVER_KEY (the server's X25519 public key, 64 hexadecimal characters) and LOCAL_PORT (80 for the web page or 23 for Telnet). Enabling requires HOST, SERVER_KEY and an admin password. Settings are saved and the device restarts at once; the tunnel starts about one minute later. The server must know this device's public key (ntun.public_key in the state); otherwise ntun.status reports that the server closed the handshake. The device key is created by the firmware and is never exported or replaced through the API.

## WireGuard

POST /wg_apply.html with ENABLED (0 or 1), ADDRESS (this device's IPv4 address and prefix in the tunnel, prefix 8-32; the prefix is routed through wg0), PEER_PUBLIC_KEY (the server's WireGuard public key, 44 base64 characters), ENDPOINT (server host name or IPv4 address), PORT (1-65535, usually 51820), KEEPALIVE (0-3600 seconds; 25 recommended behind NAT) and PRESHARED_KEY (44 base64 characters, empty for none, or "keep" to keep the stored one). Enabling requires ADDRESS, PEER_PUBLIC_KEY, ENDPOINT and an admin password. Settings are saved and the device restarts. The client is initiator only: it rekeys every 2 minutes and does not answer handshakes started by the server, so use a keepalive. Before the first handshake it gets the time by SNTP from pool.ntp.org (WireGuard rejects stale timestamps). The device key is generated by the firmware; it is never exported or replaced through the API.

## Firmware tests and recovery

Telnet uses TCP 23 and accepts logins only when an admin password is set and the device network uses WPA2; otherwise it explains why and refuses. Authenticate with the admin credentials supplied by the owner. The serial console needs no login. At CMD>, use help and ramboot status. Use up to leave submenus.

ramboot check <TFTP-server> <file.img> downloads and validates a complete uImage including its header. ramboot boot <TFTP-server> <file.img> downloads, validates and executes it in RAM, dropping connections. Neither command installs firmware. Use a compatible image and an authorized TFTP server.

Normal flash driver writes are blocked except for the explicit configuration-save operation, limited to config data at offsets 0x31000–0x35fff. Erasing preserves other bytes of its physical sector 0x30000–0x3ffff. Bootloader/environment and calibration are outside this sector. A power cycle boots the installed firmware; hardware watchdog recovery requires compatible test firmware that preserves the watchdog. A network-only hang may need a power cycle. Never use direct flash-write commands during an inspection.

## Explicit firmware installation

ramboot install-check <TFTP-server> <file.img> validates the complete uImage and flash geometry without writing. ramboot flash-info reports CRC32 checks of boot/environment, config sector and calibration. ramboot flash-read <offset> <length> reads up to 256 bytes of the config sector for a private backup.

Only with explicit owner authorization, ramboot install <TFTP-server> <file.img> CONFIRM-FLASH downloads and validates the image, erases firmware blocks starting at 0x50000, programs and verifies the payload, then commits the uImage header last and verifies the complete result. Check ramboot status for state=installed, busy=0, error=none. It does not reboot or save configuration. Never interrupt power during installation. Power cycling after successful installation starts the new resident image.
